# AI 起名平台

一个部署在 Vercel 上的 AI 起名小应用：输入需求（如「男孩、国风、简约」），大模型流式输出 3 组名字和寓意，历史记录存入 Supabase。

## 功能

- **SSE 流式输出**：名字一个字一个字显示，不用等整段生成完
- **多模型切换**：`modelConfigMap` 统一配置豆包（火山方舟）/ DeepSeek / 通义千问 / Kimi，一套调用代码适配全部
- **历史记录**：每次起名需求、结果、所用模型写入 Supabase `name_history` 表
- **密钥安全**：全部从环境变量读取，`.env` 已在 `.gitignore` 中，不会提交

## 建表 SQL

```sql
create table if not exists name_history (
  id bigint generated by default as identity primary key,
  user_requirement text not null,
  name_result text not null,
  model_name text not null,
  created_at timestamp with time zone default now()
);

alter table name_history enable row level security;

create policy "name_history_read" on name_history for select using (true);
create policy "name_history_insert" on name_history for insert with check (true);
```

## 环境变量

| 变量名 | 说明 |
|---|---|
| `SUPABASE_URL` | Supabase 项目地址 |
| `SUPABASE_ANON_KEY` | Supabase 匿名密钥（publishable） |
| `DOUBAO_API_KEY` | 火山方舟 API Key |
| `DOUBAO_MODEL` | 豆包模型名或推理接入点 ID，默认 `doubao-seed-1-6-250615` |
| `DEEPSEEK_API_KEY` | DeepSeek Key（可空） |
| `QWEN_API_KEY` | 通义千问 DashScope Key（可空） |
| `KIMI_API_KEY` | Kimi Key（可空） |

只配置其中一个也能跑，前端下拉框里没有密钥的模型会显示「未配置密钥」并置灰。

## 本地运行

```bash
npm install
cp .env.example .env    # 填入真实密钥
npm run dev             # 打开 http://localhost:3000
```

## 部署到 Vercel

1. 导入 GitHub 仓库
2. Settings → Environment Variables 填入与 `.env` 一致的变量
3. Deploy，拿到公网网址

## 为什么只改 configuration 就能切模型

四家平台都提供 OpenAI 兼容网关：`/v1/chat/completions`（千问是 `compatible-mode/v1/chat/completions`）。入参 `messages`、`stream:true`，SSE 分片结构 `choices[0].delta.content`，鉴权头 `Authorization: Bearer xxx` 全部对齐 OpenAI 标准。所以后端只写一段 fetch，循环读取配置表即可。
